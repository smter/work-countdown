# 提醒类别由来源决定：日历来的算会议，手动加的算日程

每条提醒只记来源（飞书日历 / 手动添加），类别直接由来源推出：日历来的算会议，用会议提前量；手动加的算日程，用日程提前量。单条提醒仍可在数据里单独覆盖提前量。

这样零配置：加日程的人不需要再选一次类别，也不用维护一个「类别」字段和它的校验。作者的使用方式也吻合——日历里的是会，手动加的是「三点半去取快递」这类不进日历的事。

**考虑过的选项**

- 每条提醒带显式类别字段，界面上给一个选择器：更准确，但每次手动加日程都多一次选择，而且要处理「类别为空」的旧数据。
- 只用一个全局提前量：最简单，但会议和琐事本来就不该提前同样久。

**后果**

手动添加的一场真会议会被归为日程，用日程提前量提醒。想改这个取舍的人要动的是「类别从哪来」，不是「提前量怎么算」——两者在代码里是分开的两层。
